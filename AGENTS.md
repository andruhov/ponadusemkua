# Миколаїв понад усе

Інструкції для будь-якого агента, який працює з цим репозиторієм.

Лендінг ГО «Миколаїв понад усе» / NGO “Mykolaiv First”: хто ми, фотозвіти, банки Monobank, реквізити.

Живий сайт: https://andruhov.github.io/ponadusemkua/

## Правила

Діють завжди, навіть якщо запит їх не повторює.

1. **Редагування руками.** Людина редагує код, він має бути зрозумілим та містити коментарі з поясненнями. Тексти й реквізити живуть у `content/`, фото й PDF — у `public/`. Новий напрямок = новий об’єкт у `directions.jsonc` плюс тека `public/work/<slug>/` з фото (без нового маршрутного файлу і без правок `src/`). Імена тек, файлів і полів мають бути зрозумілі без пояснень. Не ховайте дані в код і не додавайте генератори, абстракції чи зайві шари, якщо через них людина вже не знає, куди класти рядок або фото.

2. **Швидкість і зручність.** Лендінг має відкриватися швидко і бути зручним на десктопі та на телефоні. Не тягніть зайві бібліотеки, шрифти, скрипти й мертві файли. Оригінали фото не стискайте і не змінюйте розмір. Фото напрямку лежить лише в `public/work/<slug>/`; слайди головної — лише в `public/slideshow/`. Не дублюйте той самий файл у кількох теках напрямків. Нижче першого екрана ставте зображенням `loading="lazy"`. Верстка має читатися й натискатися пальцем на вузькому екрані; після змін UI перевіряйте обидва розміри.

3. **Реквізити для донатів.** Не змінювати `content/donate.jsonc` без явного підтвердження людини. Реквізити не вигадувати, не «виправляти» і не форматувати з міркувань стилю.

## Стек

Vite 8, React 19, TanStack Start/Router, Tailwind v4. Статичний деплой на GitHub Pages через Actions (`.github/workflows/pages.yml`). Коли `GITHUB_PAGES=1`, Vite `base` — `/ponadusemkua/`.

## Що правити

| Що змінюється | Де |
|---|---|
| Тексти (UK/EN), реквізити, банки, соцмережі | `content/` — див. `content/README.md` |
| Напрямки роботи | `content/directions.jsonc` + фото в `public/work/<slug>/` |
| Слайди першого екрана | `public/slideshow/` |
| PDF рахунків | `public/pdf/` |

Новий напрямок = новий об’єкт у `content/directions.jsonc` (slug, href кнопки «Підтримати цей напрямок», тексти) і тека `public/work/<slug>/` з фото. `href` — будь-яка http(s)-адреса, не обов’язково банка з `donate.jsonc`. Шляхи до знімків у jsonc не пишуть — сайт читає теку сам. Окремий файл маршруту не потрібен.

Маршрути: `/` (українська), `/en` (англійська), `/eng` — редірект на `/en`. Сторінка напрямку: `/napryamky/<slug>` і `/en/napryamky/<slug>`.

## Команди

```bash
npm ci
npm run dev          # http://127.0.0.1:8080/
npm test
npm run typecheck
npm run build        # збирає в docs/ (у git не комітити)
```

На Windows викликайте `npm.cmd`, не `npm`. Vite стартує через `scripts/with-app-env.mjs` (локальний `node` + `vite.js`), не через `vite.cmd`.

## Деплой

Source у GitHub Pages — **GitHub Actions**. Пуш у `main` проганяє тести, typecheck і збірку, потім викладає `docs/`. Каталог `docs/` і зібраний HTML у корені репозиторію не тримаються.

Джерело статичних файлів — `public/`. Після змін потрібен пуш; комітити зібраний сайт не треба.

## Перевірка UI

Якщо змінюєте те, що бачить відвідувач (верстка, маршрути, контент на сторінці), перевірте українську й англійську версії на широкому екрані й на телефоні. Playwright локально може бути не встановлений — тоді дивіться зібраний HTML у `docs/` після `npm run build`.
